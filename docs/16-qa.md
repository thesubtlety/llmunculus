# 16 qa review

A senior QA pass over the whole project: three parallel review agents (security/memory, build/embed, docs/loop) plus mechanical checks (warning-clean build, all examples through the child, self-test, symbol guard). Findings and what was done.

## the shape of the results

The design held up. No crashes in the loop, no infinite retries, exit codes consistent, TLS verification genuinely enforced, the embedding and zip64 parsing solid, `--remote` quoting correct. The real defects were three kinds: memory-safety in the C, missing build dependency edges, and doc/matcher drift. All fixed and re-verified.

## fixed: memory safety and security

| bug | severity | fix |
|---|---|---|
| jb_run escape buffer `2*n+16`, needs `4*n` (heap overflow on any quoted command) | high | `4*n+16`. confirmed with ASan before, clean after |
| tls.c concatenated body into `req[2048]`, sent stack memory past it for bodies >2KB (reports are 8KB) | high | write header, then the body as its own `mbedtls_ssl_write` |
| read-only mode bypassable: `remove`, `freopen`, `openat`, `tmpfile`, `pwrite`, `fdopen` unwrapped | high | wrappers added and registered. verified: writes refused, no file created, reads still work |
| report_json / http_post snprintf-accumulation past stack buffers | high/med | bounded APP/APPS macros that stop at cap; header-length guard |
| SIGPIPE could kill the agent when a child or peer dies mid-write | med | `signal(SIGPIPE, SIG_IGN)` at startup |
| connect() with no timeout hangs on a dead host (report path is in-process) | med | non-blocking connect + poll timeout in tls.c, report.c, and the socket examples |
| win32 privilege/service loops: snprintf accumulation | med | `if (used >= cap) break;` |
| embed.c zip64 extra-field reads unbounded; tls.c response unbounded + realloc unchecked | low | bounds checks; 1 MB response ceiling; realloc checked |

An important note on the fix pass itself: the first attempt added the read-only wrapper *definitions* but not the array *entries*, so nothing fired and a naive test passed on an ENOENT. Caught by testing a file that did not exist yet. QA the QA.

## fixed: build dependency edges

Every "silent stale artifact" bug this project hit traces to missing prerequisites. Closed:

- `build/jb` and `build/runtest` now depend on `$(wildcard src/*.h)`: editing any header rebuilds.
- `consts.c` now depends on `examples/*.c`, `profile/*.c` and both index files: editing an example or section refreshes the embedded copies. No more `rm consts.c` by hand.
- the jb recipe does `rm -rf build/obj` first: a renamed source's orphan object can no longer link in.
- a real `tcc-patch` rule applies `patches/tcc-dual-mem.patch` idempotently, so a fresh clone keeps the macOS memory fallback.

## fixed: matcher and docs

- The example matcher was rebuilt around shared-word eligibility: two shared words qualify, one shared word only if it is in at most two examples, highest score wins, no absolute floor. This fixed both the generic-verb mis-picks (`show`, `list`, `run` are now stop words) and the dilution that had started rejecting correct matches as the library grew. The plural stemmer now collapses `addresses`/`address`.
- Stale doc numbers corrected: the matcher floor in 12-helpers, the portability status header, the M9 framing in decisions, and the protocol grammar block (which still showed the pre-DO grammars) now points at `src/grammar.c` with the current shapes.
- Two example fixes: `disk_per_mount` percent now matches `df` (over used+avail, not total); the file examples create `jbtest/` so they run standalone.

## still open, by choice

- `which ports are open` returns no example, because `port` is now in four examples and a single common word should not match. Honest miss; the model handles it. Fixable only by a two-word phrasing or more coverage.
- Content-word near-misses (`cpu temperature` to the cpu-model example) remain: the closest example when none fits. Inherent to bag-of-words; coverage is the only lever.
- The win32 wrappers, the dual tcc memory mode, and the macOS/Windows profile branches are written but unrun where it matters.

## verification after fixes

Warning-clean build, `check-syms` ok, self-test ALL PASS, `--explore` clean, the security repros all behave (overflow gone, read-only refuses writes, large-body TLS sends cleanly), and header/example edits now trigger rebuilds.
